# amocrm-pro-service: полный пакет 0.6.2

Пакет восстанавливает диагностический интерфейс прежней интеграции
`sub-projects/amocrm-pro-service` (0.1.2) и добавляет распределение отдельным
блоком. Activity и интеграция `amo-pro-service-2` в пакет не включены.

Распределительный ZIP 0.1.2 содержал только manifest, i18n, изображения и
distribution adapter. Его установка поверх полного виджета заменяла прежний
script.js и исключала прежние настройки `backend_url` и `integration_code`.

В полном пакете сохранены прежний backend client, настройки, переводы, стили,
изображения и действия bootstrap/ping/set-status/configure-rule. Скрипт прежнего
виджета перенесён в `lib/legacy-widget.js`; относительные AMD imports исправлены.
`script.js` объединяет жизненный цикл обоих модулей; distribution adapter
монтирует собственный блок внутри существующей карточки, не заменяя её.

Дополнительно исправлены fallback на `APP.constant('card_id')` и монтирование
настроек в собственный контейнер. Глобальные поиски `*_custom_content` и запись
в первый чужой `*_custom` удалены. DP настройки и endpoint сохранены из
опубликованного распределительного архива aa7e556c.

Runtime bundle закреплён на существующем серверном файле
`rkrs-distribution.ce6a9cbc0f0ae97f.umd.js`. Панель читает данные каждые 15 секунд
в видимой вкладке. Эти чтения не являются распределением; назначения выполняет
серверная цепочка событий и worker. Серверный сбой runtime 503 проверяется
агентом pi отдельно от состава ZIP.

Проверка: `node --test verify.test.cjs` — 10 тестов DOM и реальных callbacks;
прежние `backend-client.test.mjs` — 9 тестов. Синтаксис всех трёх адаптеров
проверен `node --check`. Архив: `python3 pack.py`.

Установка: заменить пользовательский архив существующего amocrm-pro-service
на `amocrm-pro-service-0.6.2.zip`, сохранить интеграцию и обновить тестовую
карточку. Убедиться, что сохранённые backend_url/integration_code корректны;
OAuth credentials не меняются; при выборе группы сервер выдаёт отдельный
ограниченный ключ DP и виджет сохраняет его скрыто. Установка сама не добавляет триггер
на этап и не переключает источник запуска правила. Для DP необходимо отдельно
настроить действие amoCRM и соответствующий источник в группе TeamOS.

Проверка принятия нового архива и отрисовки в настоящем amoCRM ещё требуется
после загрузки; локальные тесты не заменяют эту проверку. Live rules и реальные
сделки при сборке не менялись.

## Версия 0.6.1: выбор группы в Digital Pipeline

Полный пакет 0.6.1 заменяет видимый ввод UUID группы на select с названиями
групп, загружаемыми через существующий авторизованный runtime `kind=groups`.
Исходный input `groupId` остаётся скрытым: выбор передаёт UUID через input/change
события, и amoCRM сохраняет его в прежнем контракте действия.
Callback без аргументов находит контейнер действия по маркеру собственного
widget_code. Чужие настройки не изменяются.

При недоступном сервере или запрете доступа select блокируется и показывает
ошибку с повтором загрузки. Сохранённый UUID не затирается, даже если группа
отсутствует в ответе. Названия выводятся как текст; ответ после закрытия окна
игнорируется. Поле существующего ключа подключения сохраняется. Новые ключи
не создаются и не извлекаются из сервера.

Проверка: 7 DOM/callback тестов, включая выбор и события сохранения, чужие поля,
403 → повтор → успех, отсутствующую сохранённую группу и закрытие окна.
Архив собирается через `python3 pack.py`. Для применения пользователь должен
загрузить полный `amocrm-pro-service-0.6.1.zip` в существующую интеграцию и
обновить страницу настроек воронки. После установки требуется реальная проверка
открытия триггера, выбора по названию и сохранения группы в amoCRM.
Версия 0.6.1 на момент сборки в amoCRM не установлена.


## Версия 0.6.2: автоматическое подключение триггера

Пользователь выбирает группу; виджет вызывает авторизованный runtime
`{kind:"dp_settings", write:true, groupId}` и получает отдельный ключ запуска
DP, привязанный к выбранной группе. Поле key и его подпись скрыты, служебное
значение сохраняется через стандартные события amoCRM. Ответ обязан содержать
`state=connected`, тот же groupId и ключ формата `dp_…`. В UI только статус
«Подключено к TeamOS» и название группы.

При смене группы старый ключ очищается. Запоздалый ответ для другой группы
игнорируется. При ошибке доступен ручной повтор; callback onSave запрещает
сохранение незавершённого подключения. Уже сохранённый старый ключ при открытии
того же триггера сохраняется до успешной автоматической настройки.

10 DOM/callback регрессий проверяют обе настройки и старый интерфейс,
скрытие ключа/подписи, обмен с dp_settings, сохранение в скрытые поля,
запоздалые ответы, отказ доступа, повтор и обязательность готового подключения.
Для полной проверки требуется серверный контракт dp_settings и установка
полного архива 0.6.2 в существующий amocrm-pro-service. Архив сам не добавляет
новый webhook или триггер и не меняет режим распределения/графики.
