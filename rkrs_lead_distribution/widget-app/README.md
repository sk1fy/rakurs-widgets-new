# Ракурс — распределение сделок

Отдельный продукт `rkrs_lead_distribution`. Старый прототип `rkrs_activity_panel` не изменён. Бизнес-правила, очередь, графики и round-robin находятся в TeamOS backend; CRM-эффекты выполняет Core (`amocrm-pro`). Виджет показывает серверные данные и отправляет команды настройки, никогда не назначает ответственного из браузера.

## Локально

```sh
npm ci
npm test
npm run dev
```

Открыть http://127.0.0.1:5178. Стенд **явно использует фикстуру SDK**, искусственные данные и не обращается к amoCRM. Настоящие RequireJS → AMD loader → pinned UMD и Shadow DOM соответствуют пути загрузки установленного виджета. Фикстура авторизации и сценарии preview не входят в UMD или ZIP. Можно переключать настройки/карточку, подключение, права, недоступность, конфликт и неизвестный результат. Это не проверка установки в amoCRM.

`npm run build:preview` создаёт автономный стенд с ресурсами в `dist-preview`; он тоже использует только фикстуру.

## Настоящий API

Loader использует документированный `self.$authorizedAjax`, amoCRM добавляет `X-Auth-Token`. Токен не извлекается, не пишется в storage, query string или логи. Core проверяет JWT и выводит scope из текущего подключения, а не account/user ID из браузера. Адрес API задаётся во время упаковки, API не подменяется ответами preview при ошибке.

- `GET /api/v1/widget/distribution/bootstrap`: проверенная личность, подключение, права, разрешённая ссылка TeamOS.
- `POST /api/v1/widget/distribution/runtime`: bounded reads `rules/groups/references/lead/history/observations`, writes `rule/group/action`.
- Все изменения имеют UUID requestId. В действии очереди тот же UUID передаётся внутри payload. История/действия карточки обязательно содержат текущий leadId.
- Редактор использует expectedRevision. Конфликт сохраняет черновик; отдельная кнопка перечитывает версии и требует осознанного сохранения пользовательских значений. Сохранение правила не уничтожает несохранённые изменения состава группы и наоборот.
- Отправленный запрос с неизвестным результатом блокирует новые действия. Явная проверка повторяет точный прежний envelope и requestId; автоматического POST-повтора нет. Ответ 202 не отображается завершением.
- Настройки воронки/этапа, сохранение текущего ответственного, пауза, состав/порядок/исключение участников изменяют общую модель TeamOS. Графики/часовой пояс и создание самой группы — в TeamOS. Если сервер не настроил ссылку, она не выдумывается браузером.

## Жизненный цикл

`render/settings/advancedSettings` монтируют один экземпляр. Идентичность учитывает аккаунт, пользователя, карточку и экран. Повторный render идемпотентен; новый settings target после закрытия создаёт новый host. `destroy` отменяет AJAX, удаляет таймер и visibility listener, чистит Shadow DOM и узлы только своего экземпляра. Поздние callbacks старой генерации не показывают данные. Новая несохранённая карточка с ID 0 не выполняет запросов.

Опрос ограничен одним циклом каждые 15 секунд, не выполняется параллельно и останавливается в скрытой вкладке/после destroy. Черновик остаётся на экране при фоновом чтении; фокус при явном обновлении восстанавливается. После утраты прав данные предыдущей карточки очищаются. История имеет страницы по 20, повторное открытие заменяет предыдущую страницу.

## Выпуск и откат

```sh
npm run release
npm run package:widget -- --assets-url https://ASSETS-HOST/distribution --api-url https://CORE-HOST/api/v1/widget/distribution
```

**Адреса выше — шаблоны, сервер ещё не выбран.** ZIP с `example.test` из тестов — проверочный артефакт, он не предназначен для настоящей установки.

Release содержит SHA-256 фактических байтов, хешированное имя bundle, версию. ZIP фиксирует конкретный bundle: одна версия архива не переключается на другой код автоматически. URL допускаются только HTTPS без credentials/query/fragment; архив не содержит placeholders, локальной конфигурации, секретов, node_modules или preview. ZIP повторно получается побайтно одинаковым при одинаковом исходном коде, lockfile и конфигурации; файловые даты нормализованы.

Порядок публикации: разместить bundle и проверить его SHA-256 → сохранить предыдущие bundle/ZIP/release.json → атомарно заменить release.json → обновить ZIP в тестовой интеграции. Bundle: `Cache-Control: public,max-age=31536000,immutable`; release.json: `no-cache`. Loader использует pinned имя, release.json нужен для выпуска/сопоставления, не меняет уже установленные ZIP. Для отката вернуть предыдущий ZIP и его bundle; не удалять старые bundle. Загрузка AMD и API должны быть разрешены политиками хоста/CORS. Core CORS допускает только точный проверенный домен аккаунта, с `X-Auth-Token`.

## Проверки и отложенная приёмка

Unit/lifecycle: SDK error/unknown semantics, отсутствующие права/связь, поздние ответы, навигация, destroy, повторное открытие настроек, SHA-256 и ZIP reproducibility. Browser QA использует Chromium/Playwright (доступен в соседнем TeamOS), 1440/390 px, ошибки/конфликт/сохранение/историю и отсутствие переполнения; сценарии сохранены в `scripts/browser-qa.mjs`, запуск `TEAM_OS_PACKAGE=/absolute/team-os/package.json node scripts/browser-qa.mjs` при работающем стенде.

Живая приёмка РС-08.3.2 остаётся незавершённой: нужен тестовый сервер/домен, интеграция и тестовый аккаунт amoCRM. Проверить установку ZIP, настоящий SDK/JWT/CORS/OAuth, разные роли, связь TeamOS, сохранение из обоих интерфейсов, реальные вебхуки/сделку, навигацию и продолжение серверной обработки после закрытия браузера. Не выдавать локальную фикстуру за это E2E. Digital Pipeline action — отдельное расширение.

Официальные SDK источники: [механика и authorizedAjax](https://www.amocrm.ru/developers/content/web_sdk/mechanics), [APP и current_card](https://www.amocrm.ru/developers/content/web_sdk/env_variables), [области](https://www.amocrm.ru/developers/content/integrations/areas), [расширенные настройки](https://www.amocrm.ru/developers/content/web_sdk/settings).

## РС-10: режим наблюдения

Режим правила `observe` — предварительная проверка без назначения, рабочей очереди,
claims и продвижения round-robin. Настройки виджета и TeamOS используют одно правило.
Новое правило для уже существующей группы создаётся приостановленным в observe;
графики и создание группы остаются в TeamOS. Старый или неизвестный режим явно
показан как неподтверждённый: переключатель выключен, поле не записывается молча.
409/частичное сохранение группы сохраняет выбранный режим в черновике.

Карточка разделяет свежие «Факты amoCRM» (currentLead.observedAt), исторического
ответственного в наблюдении и предлагаемого сотрудника. latestObservation не является
подтверждением назначения. Если в текущей области нет записей назначения, показана
только эта ограниченная область, без вывода о всей истории сделки.
Журнал читается для выбранного правила страницами по 20; источник проверяет права
на каждую сделку. Ошибка/неполный HTTP200 не превращается в пустой успех. При потере
прав прежние закрытые данные очищаются. Неизвестный тип решения остаётся неизвестным.

Observe → live создаёт новую границу, прошлые наблюдения не исполняются. Новые входы
после границы могут ждать возобновления при паузе. Backend блокирует смену режима
при незавершённой рабочей очереди; браузер не отменяет её и не назначает ответственного.

Локально: 10 unit-тестов, pinned UMD/ZIP reproducibility, preview-сборка,
12 прежних и 8 новых браузерных SDK fixture сценариев (1440/390, ночь, разные
ответственные/предложение, 409, частичное сохранение, режимы, неизвестные значения).
Для новых сценариев: `TEAM_OS_PACKAGE=/absolute/team-os/package.json node scripts/browser-qa-observe.mjs`.
Настоящая установка/авторизация SDK в amoCRM остаётся РС-08.3.2, OAuth — РС-03.1.2.

Каноническая матрица: amocrm-pro `docs/specs/lead-distribution-v1/11-local-acceptance.md`;
пилот: `docs/runbooks/lead-distribution-pilot.md`. Сначала сервер с CRM fixture для
сети/рестартов/backup, затем рекомендуемый тестовый сервер + отдельный amoCRM аккаунт,
интеграция, домен, 2–3 сотрудника и искусственные сделки. Установить собранный для
реальных HTTPS адресов ZIP, проверить G1–G6 runbook, общие настройки обоих UI и фактическое
назначение только после явного live gate. Альтернатива — HTTPS tunnel к локальным сервисам;
admin listener и межсервисный транспорт остаются приватными. Production переключение
и установка не выполнялись, example.test ZIP служит только проверке упаковки.
