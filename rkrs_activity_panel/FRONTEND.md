# Новая версия приложения активности

Статус на 30.09.2026: в `frontend/` собран запускаемый прототип на Vue 3 + Vite по [новому концепту](https://claude.ai/code/artifact/adb5bb7b-1de4-42e4-a4bd-85cb33107551). Цвета и фон дня используются во всех режимах. Неделя и месяц пока представлены фиксированными демоданными без расчётной логики и API. Дневной экран тоже работает на демоснимках до подключения backend. Инструкция запуска и контракты компонентов — в [frontend/README.md](frontend/README.md).

## Задача и границы

Подготовить развитие приложения из текущего `rkrs_activity_panel/vue` с новым функционалом активности по неделе и месяцу. Приложение и виджет будут отличаться. Архитектура интеграции с amoCRM описана отдельно в [WIDGET.md](WIDGET.md).

По уточнению от 30.09.2026 неделя и месяц реализованы как экраны просмотра аналитики по концепту. Расчёты и API этих периодов ещё не готовы и не реализуются на текущем этапе. Ручное добавление записей в текущий объём не входит.

## Текущая база

Исходники: `/Users/nikpeskov/Projects/rakurs/rakurs-widgets-dev/rkrs_activity_panel/vue/`.

В исходном проекте используются Vue 3, JavaScript, Pinia, Ant Design Vue, dayjs и Vue CLI. Новый прототип сохраняет Vue 3 и JavaScript, использует Vite, отдельные компоненты и общие CSS-токены. Пример React-загрузчика относится к архитектуре виджета.

Ключевые части исходного приложения:

| Часть | Файлы относительно `vue/` |
| --- | --- |
| Основной вход и выбор URL-режима | `src/main.js`, `src/App.vue` |
| Дашборд и экран сотрудника | `src/components/Dashboard/DashboardView.vue`, `src/components/EmployeeStatsScreenV2/EmployeeStatsScreenV2.vue` |
| Настройки и отдельный библиотечный вход | `src/components/SettingsView.vue`, `src/mainProd.js` |
| Состояние и данные активности | `src/stores/dashboardStore.js`, `src/stores/activityStore.js`, `src/stores/externalActivityStore.js` |
| API и работа со временем | `src/api/client.js`, `src/api/services/tableService.js`, `src/api/services/externalActivityService.js`, `src/utils/timeUtils.js` |

`App.vue` поддерживает основной режим (`type=main` или без `type`), панель задач (`type=missed`) и операторский виджет (`type=employee`). Библиотечный вход `mainProd.js` монтирует экран настроек. Совместимость этих режимов нужно учесть при определении новой структуры.

## Подготовка недельных и месячных сценариев

Текущий интерфейс и расчёты во многом привязаны к выбранному дню: дашборд загружает его рабочий интервал, а внешняя активность кэшируется по дате и сотруднику. Сервисы `getTable` и `getActivityHistory` уже передают диапазон дат. Это точка расширения, но работоспособность и полнота недельных/месячных ответов backend ещё не проверены.

Предварительные направления работы после уточнения сценариев:

- Ввести общее представление выбранного периода: тип, начало, конец и часовой пояс, сохранив дневной сценарий.
- Определить начало недели, календарный или скользящий месяц, границы диапазона API и правила неполного текущего периода.
- Согласовать расчёт итогов, процентов, рабочего времени и пересекающихся активностей за несколько дней.
- Адаптировать загрузку, кэш и автообновление к диапазонам; проверить ограничения API и не строить месячный экран на неконтролируемом числе запросов по дням и сотрудникам.
- Привязать представление данных и переключение периодов к готовому дизайну.

Это направления подготовки, а не утверждённый контракт API или готовое техническое задание.
