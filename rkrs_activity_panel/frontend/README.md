# Фронтенд «Контроль активности»

Локальный прототип на Vue 3 + Vite по [концепту](https://claude.ai/code/artifact/adb5bb7b-1de4-42e4-a4bd-85cb33107551). Для дня, недели и месяца используется единая палитра дневного экрана. Основные иконки — `@lucide/vue`; контуры иконок шапки перенесены из концепта в `ReferenceIcon.vue`.

## Запуск

Нужен Node.js 20.19+ или 22.12+ (актуальная LTS-версия подойдёт).

```sh
cd /Users/nikpeskov/Projects/rakurs/rakurs-widgets-new/rkrs_activity_panel/frontend
npm ci
npm run dev
```

Dev-сервер доступен по адресу, который Vite выводит в терминале (обычно `http://127.0.0.1:5173`). Production-сборка: `npm run build`; локальный просмотр сборки: `npm run preview`. Проверки календарных границ, настроек и согласованности дневных демоданных: `npm test`.

## Что реализовано

- День: группы и выбор сотрудников, независимые поиск, сортировка и компактный вид внутри каждого отдела, сворачивание группы, метрики, шкала активности, окно сотрудника. Пустой результат поиска и сброс фильтра затрагивают только соответствующий отдел.
- Общий выбор сотрудников сохраняется между режимами; настройки отображения и выбор сохраняются в localStorage. Ошибка доступа к хранилищу не мешает работе приложения.
- Переключение периода, календарь и переходы назад/вперёд. Дневные примеры доступны за 23 и 24 сентября 2026 года; остальные даты показывают отсутствие демоснимка. Время демо зафиксировано на 24 сентября, 15:40.
- Неделя/месяц: итоговые карточки, почасовая таблица с тремя режимами, таблица сотрудников, два графика, сравнение рабочих дней и переход в дневной просмотр.
- Адаптивная верстка, доступные подписи, управление вкладками стрелками/Home/End, нативные модальные окна с Escape и удержанием фокуса.

## Границы прототипа

Приложение работает **только на демоданных**. Сетевых запросов к API, авторизации, записи данных и подключения amoCRM здесь пока нет. Кнопки уведомлений открывают демонстрационные списки либо сообщение о недоступной детализации.

Недельные и месячные показатели — фиксированные значения для проверки дизайна. Фильтры управляют видимыми сотрудниками и днями, но не пересчитывают итоги, графики, медианы или рейтинги. Верхняя плашка сообщает об этом. Перемещение по календарю меняет подпись и набор дат; оно не загружает и не рассчитывает аналитику. Будущие дни относительно демоснимка недоступны для выбора.

## Структура и подключение данных

| Файлы                                 | Ответственность                                             |
| ------------------------------------- | ----------------------------------------------------------- |
| `src/App.vue`                         | Общая оболочка, выбор периода/сотрудников, окна и настройки |
| `src/style.css`                       | Общие токены дневной палитры и адаптивная оболочка          |
| `src/components/DayOverview.vue`      | Группировка дневных сотрудников по отделам                   |
| `src/components/DayDepartment.vue`    | Карточки отдела и собственное состояние его фильтров         |
| `src/components/ActivityTimeline.vue` | Отрисовка интервалов по переданным данным                   |
| `src/components/Period*.vue`          | Макеты недели, месяца, графиков и сравнения дней            |
| `src/data/demo.js`                    | Два явных дневных демоснимка и справочник сотрудников       |
| `src/data/periodFixtures.js`          | Статичные значения периодных макетов                        |
| `src/utils/periods.js`                | Календарная навигация и безопасное чтение настроек          |

`DayOverview` принимает `employees`, `date`, `isDemo`, `loading`, `showComparisons`; событие `select-employee` передаёт выбранного сотрудника. Форма строки:

```js
{
  id: 'employee-id', name: 'Имя', groupId: 'group-id', groupName: 'Отдел',
  tone: 't', rating: 50.5, callMinutes: 42,
  metrics: {
    calls: [2, 3], messages: [8, 12], emails: [3, 5],
    tasks: [10, 13], deals: [4, 6]
  },
  noTasks: 0, overdueDeals: 4, overdueTasks: 6,
  timeline: [{ start: 0, duration: 15, type: 'crm' }]
}
```

`rating` — проценты 0–100; пары метрик — выбранный/предыдущий день; неизвестное значение — `null`. `timeline.start` и `duration` — минуты от 09:00, тип — `crm`, `call`, `idle` или `future`.

Исходный frontend использовал `POST /getTable` с `date_from`, `date_to`, `amo_account_id`, `app_name`, `managers`, `pipelines`, но совместимость с новым backend ещё не подтверждена. Не переносить тестовый accountId из старого проекта. Контракты недельной и месячной аналитики согласовать отдельно, затем заменить `periodFixtures`.

Загрузчик amoCRM (`widget/script.js`) и старый проект этой реализацией не изменяются.
