# Проверить live-панель с локальным SDK

Из `rkrs_activity_panel/widget-app` выполните `npm run dev:live-fixture`.
Откройте [fixture](http://127.0.0.1:5176/live-fixture.html?scenario=error).
Vite импортирует настоящие `runtime.js`, `live-controller.js` и Vue-панель.
`live-sdk.js` отвечает через SDK `$.ajax` в памяти. Все API origins используют
`.invalid`. Неизвестный origin отклоняется. Запросы в CRM не отправляются.

Навигация над карточкой перезагружает fixture и сбрасывает его состояние.
Сценарий `error` начинает с одной ошибки state. `error-disabled` также задаёт
кэш отключённой панели. `auth` отклоняет один запрос disposable token.
`active` восстанавливает интервал `fixture-work`, а `idle` показывает очередь.
Выберите следующий enabled или disabled перед нажатием **Обновить данные**
в панели, чтобы проверить оба ответа после первоначальной ошибки.

Для проверки native completion выполните следующие действия.

1. Откройте `?scenario=active`.
2. Нажмите **Удерживать task detail**, затем штатную кнопку **Выполнить**.
3. Подождите больше 7 секунд. В статусе остаётся одно чтение detail и ноль stop-команд.
4. Нажмите **Fixture hidden = false**. Флаг станет true.
5. Нажмите **Вернуть task detail**. Интервал остаётся активным без stop-команды.
6. Верните hidden в false. В пределах следующего шага 5 секунд появится одна stop-команда.

Чтобы проверить скрытие во время обязательного state-чтения, перезагрузите
`active`, нажмите **Удерживать state**, затем **Выполнить**. Когда статус
покажет held state, включите hidden и верните state. Stop-команда появится
только после возврата hidden в false. **Ошибка task detail** отклоняет
удержанное чтение, после чего следующий видимый tick может повторить его.

Удержание действует на все следующие запросы выбранного типа.
**Вернуть** снимает удержание и завершает один ожидающий ответ.
Повторный клик завершает следующий ответ, если он есть.
Флаг **Fixture hidden** заменяет `document.hidden` только на этой странице.
Он нужен для повторяемого порядка событий и не проверяет фоновые ограничения браузера.
**Destroy + render** вызывает настоящий unmount и повторный mount runtime.

**Следующий state enabled** и **Следующий state disabled** меняют ответ SDK,
не вызывая Refresh автоматически. Native **Выполнить** сохраняет
`Fixture native completion` в записи задачи fixture. Панель сама проверяет
CRM-запись. Заголовки, меню, start, stop, пауза, форма результата, история и
компактный вид используют настоящие действия контроллера.

Ссылки на CRM-карточку и полный список задач ведут на отсутствующие в fixture
страницы. **Общие настройки аккаунта** получает ошибку unsupported request,
поскольку browser-session не эмулируется. Imbox DOM в fixture отсутствует.
Проверки этих сценариев находятся в существующих тестах и матрице приёмки.
Fixture не входит в UMD. Обычный `build:preview` собирает существующий симулятор.
