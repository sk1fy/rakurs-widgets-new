# MVP виджета сотрудников «Контроль активности 2.0»

Задача [КА-01.02](https://app.clickup.com/t/1amkccgcnzx).
Панель сотрудников написана на Vue; отдельная аналитическая React-панель
находится в `../web-panel/`. Обе используют amocrm-pro.

## Режимы

В amoCRM виджет работает через `$authorizedAjax` и текущие account/user ID.
Без SDK или данных сотрудника отображается ошибка и действия недоступны.
Ошибка API не переключает виджет на локальные данные.

Симулятор включает демо явно: `__rkrsActivityPreview = true` в экземпляре
AMD-загрузчика → `context.mode = 'demo'`. Он использует отдельную локальную
модель, задачи и storage namespace `rkrs_activity_prototype_v1`.
Наличие DOM-слота симулятора само по себе не включает деморежим.

## Минимальные сценарии

- Своя очередь незавершённых задач amoCRM, выбор, старт и остановка таймера.
- Завершение задачи через форму результата; пустой результат допустим.
  Результат ограничен 2000 UTF-8 байт контрактом Core.
- Другая активность, пауза и базовый учёт открытого диалога Imbox.
- Текущая сессия и история читаются с сервера; одна активная сессия
  обеспечивается backend, время вычисляется по серверному timestamp.
- Повтор неопределённой команды сохраняет её UUID. При частичном успехе
  amoCRM/Activity показывается восстановление предыдущей операции.
- Отключение панели блокирует новые действия; ранее запущенный интервал
  можно остановить. Новые команды недоступны до загрузки состояния.
- Число завершённых задач в live-режиме показано как «—»: непустой результат
  сессии не является достоверным признаком завершения задачи.

Реальные задачи читаются и завершаются через same-origin amoCRM API v4.
Activity state/history/commands идут через SDK с одноразовой авторизацией.
Формат задач и завершения соответствует
[API задач amoCRM](https://www.amocrm.ru/developers/content/crm_platform/tasks-api).
Статические OAuth secrets и management credentials в сборку не включаются.
Общие настройки открываются через серверный browser-session; проверка
администратора остаётся на backend.

## Запуск и сборка

Node.js 22.12+:

```sh
npm ci
npm test
npm run build:preview
# Отдельный порт, если React-панель уже занимает 5174:
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5176 --strictPort
```

`npm test` сначала собирает UMD, затем запускает модель, loader, runtime,
SDK-клиент и live-контроллер. После изменения виджета выполните
`npm run release`: симулятор загружает отдельный AMD/UMD-релиз,
поэтому одного HMR оболочки недостаточно.

Для реальной сборки задайте публичные HTTPS origins:

```sh
VITE_ACTIVITY_API_ORIGIN=https://api.example.invalid \
VITE_ACTIVITY_APP_ORIGIN=https://panel.example.invalid npm run release
```

API origin должен вести к Core; application origin — к React-панели
из allowlist Core. Это примеры, не адреса развёрнутого MVP.

`dist-remote/` содержит UMD с хешем и `release.json`; `dist-preview/` —
симулятор. Для ZIP загрузчика используется существующая команда:

```sh
npm run package:widget -- --assets-url https://assets.example.invalid/activity
```

Живой SDK-режим способен изменять задачи amoCRM. ZIP с адресом-заглушкой
не устанавливается в CRM. HTTPS-размещение, тестовый ZIP и установка
на согласованный тестовый аккаунт относятся к КА-01.04.
Порядок выпуска и отката — [mvp-release.md](../../docs/activity/mvp-release.md).

## Границы MVP

Локальные проверки транспорта и UI не подтверждают реальную установку SDK
или соответствие DOM текущей версии amoCRM. Проверка агентом на установленной
связке относится к КА-01.05, ручная приёмка пользователя — к КА-01.06.

Полные DOM-хуки карточек и штатного завершения, связанные задачи,
горячие клавиши, оптимизация всех вкладок и общий жизненный цикл платформы
остаются в КА-01.07. Backend-проверка канонического CRM-контекста,
структурированные Imbox-поля и контракт достоверного счётчика завершений
также дорабатываются отдельно. Старые storage-ключи не мигрируются.
Журнал восстановления использует sessionStorage без credentials.
Если browser storage запрещён, повтор сохраняется только в памяти;
после перезагрузки восстанавливается текущая серверная сессия,
а сохранность локального intent не гарантируется. Полная политика
хранения и синхронизация вкладок относятся к КА-01.07.
