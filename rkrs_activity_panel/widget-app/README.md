# Прототип виджета активности Rakurs

Компактная панель внутри демонстрационной CRM. Это отдельный прототип виджета; приложение аналитики находится в соседнем `frontend/`.

## Запуск

Node.js 22.12+ и npm:

```sh
cd /Users/nikpeskov/Projects/rakurs/rakurs-widgets-new/rkrs_activity_panel/widget-app
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5174/`. Команда сначала собирает удалённый модуль, затем запускает стенд. Стенд использует настоящий RequireJS и копию `../widget/script.js` с локальным адресом ресурсов: `release.json` → UMD с хешем → панель.

После изменения самого виджета (`WidgetPanel.vue`, `model.js`, `runtime.js`, `widget.css`, `../widget/script.js`) выполнить `npm run release` и обновить страницу. Vite автоматически обновляет оболочку стенда, но виджет намеренно загружается как отдельный релиз через AMD.

## Сценарии

- **Мои задачи**: выбор из очереди, старт/стоп, завершение и переход к следующей незавершённой задаче без автоматического старта.
- **Другая активность**: название от 3 до 160 символов и учёт времени.
- **Imbox**: выбор диалога и учёт времени общения. Отправки сообщений нет.
- **История**: завершённые интервалы, суммарное учтённое время и число завершённых демозадач.
- **Настройки**: компактный вид, сброс локальных демоданных. Доступны из панели и через callback `settings`.

В симуляторе можно переключаться между задачами, сделками и чатами; запускать задачу/диалог из их карточек; повторно отрисовывать, скрывать и показывать панель.

## Архитектура

| Файл                                                          | Назначение                                                            |
| ------------------------------------------------------------- | --------------------------------------------------------------------- |
| `../widget/script.js`                                         | AMD-загрузчик, callbacks amoCRM, загрузка `release.json` и UMD        |
| `../widget/manifest.json`, `i18n/ru.json`, `images/`          | Черновой комплект ZIP; изображения перенесены из исходного виджета    |
| `src/runtime.js`                                              | Монтирование, Shadow DOM, один таймер на экземпляр, удаление ресурсов |
| `src/WidgetPanel.vue`, `WidgetSettings.vue`, `WidgetIcon.vue` | Представление панели и настроек                                       |
| `src/widget.css`                                              | CSS, включённый внутрь UMD и добавляемый только в Shadow DOM          |
| `src/model.js`, `demo-data.js`                                | Локальные задачи, активность, история и сохранение состояния          |
| `src/Preview.vue`, `preview.css`                              | Демонстрационная CRM; не включается в UMD виджета                     |

Публичный контракт удалённого модуля:

```js
registerWidgetInstance(widget);
mountPanel({ widget, accountId, userId, subdomain, area });
openSettings({ widget, accountId, userId, settingsTarget });
unmountAll(widget);
```

Повторный `mountPanel` идемпотентен. `destroy` очищает только свой экземпляр: приложения Vue, обработчики, интервал и узлы со стилями. Если загрузка завершится после `destroy`, загрузчик не смонтирует устаревший экземпляр. Ошибку загрузки можно повторить следующим `render`.

В стенде используется явный `[data-rkrs-activity-panel-slot]`. Без него runtime добавляет панель в начало `#app` либо `body`. События `rkrs-activity-demo-action` и `rkrs-activity-demo-state` работают только с выделенным слотом симулятора и связывают его карточки с локальной моделью. Селекторы реальных карточек amoCRM не перехватываются.

## Состояние и границы

Всё работает **локально**, без запросов к backend/amoCRM API, авторизации, активации или изменения настоящих задач. Сохранение использует отдельный ключ `rkrs_activity_prototype_v1:<accountId>:<userId>`; ключи старого виджета не читаются и не меняются.

Одновременно учитывается одна активность. Смена сценария или задачи сохраняет предыдущий интервал. Повторный старт той же активности не сбрасывает её таймер. Перезагрузка и временное скрытие панели сохраняют запущенную сессию: чтобы закончить учёт, нажать «Стоп». Время вычисляется по timestamp, а не по количеству срабатываний интервала. Хранятся последние 100 записей; один интервал ограничен 24 часами. Многовкладочная синхронизация пока не реализована.

Встраивание в настоящий интерфейс amoCRM, его фиксированные шапки и модальные окна, права, существующие настройки и production API ещё требуют отдельной интеграционной проверки. Прототип не устанавливался в рабочий аккаунт.

## Сборка и проверка

```sh
npm test                  # сборка + loader/model/runtime tests
npm run release           # UMD, хеш и release.json в dist-remote/
npm run build:preview     # автономный стенд в dist-preview/
npm run preview           # просмотр собранного стенда на :4174
```

Тесты проверяют повторную загрузку после ошибки, поздние callbacks, независимую очистку экземпляров, таймер и восстановление, валидацию состояния, стили Shadow DOM и события стенда. В браузере проверены все три сценария, очередь, история, настройки, повторное монтирование и ширина 390 px.

## Подготовка ZIP

`../widget/script.js` содержит placeholder `__RKRS_ACTIVITY_ASSETS_URL__`: адрес сервера ещё не выбран. После размещения `dist-remote/` на своём HTTPS-хосте:

```sh
npm run package:widget -- --assets-url https://YOUR-HOST/widget-assets
```

Команда создаёт `dist-package/rkrs-activity-prototype.zip`, подставляя адрес только в копию загрузчика. В ZIP входят `script.js`, manifest, локализация и изображения, **без UMD**. Это по-прежнему демонстрационная версия.

Сервер должен разрешать CORS для `release.json`; для него нужен `Cache-Control: no-cache`, для файлов с хешем — долгий immutable-кеш. Публикация: сначала новый бандл, затем атомарное переключение `release.json`. Старые бандлы сохраняются; откат — возврат предыдущего `release.json`. Изменения загрузчика или manifest требуют обновления ZIP. Автоматического деплоя нет.
