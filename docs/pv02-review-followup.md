## Почему нельзя снять ограничения legacy одним флагом

Актуальный ADR-0040 различает server SSD grant и browser snapshot. Исключение
доступности SSD относится к серверу с durable grant, atomic guard и fence;
оно прямо не переносится в browser localStorage.

В зафиксированном snapshot widgets-dev ColorLeads держит MutationObserver в
замыканиях init и отключает его только при beforeunload. В CopyLead остаются
самостоятельные jQuery handlers; ActivationRakurs вызывает SSD install вне
общего SDK. Общие tools также предоставляют прямые CRM PATCH leads и POST
salesbot/run. В проверенных entrypoint вызовы именно этих двух helpers не
найдены: это доступные обходные пути для дальнейшей трассировки, а не доказанный
вызов каждой мутации. [Инвентарь и источники](pv02-moderation.md).

Остановка callbacks загрузчика не останавливает эти ресурсы. Допустить
reload-only legacy без полного hot-swap можно отдельным протоколом: все эффекты
за guarded admission, неподконтрольные browser writes исключены, target не
активируется до подтверждённой остановки старых клиентов и разбора in-flight.
Простая надпись «Обновите страницу» этих условий не выполняет.

Readonly retention тоже требует реализации: новый adapter.setRouteState
синхронно блокирует самостоятельные источники эффектов. Если этого контракта
нет либо он нарушен, loader снимает адаптер. Текущие snapshots не объявляются
безопасными только благодаря новому режиму отображения.

## Автоматическая приёмка исправлений

Тесты проверяют несколько TTL подряд без remount, сохранение UI при offline,
восстановление без потери экземпляра, задержанный таймер suspended browser,
таймаут фонового запроса, paused phase, границу установки, rollback-watermarks,
отзыв доступа и ошибку readonly-fence. Readonly сохранение и offline cold-start
проверяются раздельно. Проверки UI в Brave/amoCRM повторно не запускались.
