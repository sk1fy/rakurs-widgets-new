# ПВ-02: поставка пилотов и модерация

Дата проверки: 2026-10-22. Это техническая проверка требований и локальных исходников. Отправка в amoМаркет, установка в demorkrs и решение модерации не выполнены. Успешная сборка ZIP не подтверждает прохождение этих проверок.

## Решение по удалённому JavaScript

Основной кандидат поставки — ZIP с локальными AMD-модулями. Удалённый исполняемый код по умолчанию выключен. Изменяемый URL или переключатель owner не должны превращаться в механизм загрузки произвольного кода.

[Официальные требования, разделы 3.1–3.2](https://www.amocrm.ru/developers/content/integrations/requirements) предписывают RequireJS для зависимостей, запрещают прямое добавление внешнего script в head и отдельно запрещают дополнительные плагины/подключения с внешних ресурсов. Там же требуется убрать ненужные файлы, использовать UTF-8 без BOM и LF, избегать минификации; eval запрещён. Из наличия RequireJS нельзя вывести разрешение CDN-загрузки бизнес-логики. Это наша консервативная интерпретация совместно действующих правил, а не полученное индивидуальное согласование.

Если для публичного виджета нужен CDN-режим, до включения следует получить ответ amoCRM именно на эту схему: immutable JS/CSS по версии, список origins, пакетный bootstrap, маршрутизация одного владельца, кэш и откат. Зафиксировать письмо/обращение, интеграцию, версию архива, дату и допустимый объём удалённых изменений. Пока такого доказательства нет, CDN-режим не является release-ready. При отказе сохраняется локальный пакет; обновления исполняемого кода проходят обычное обновление ZIP. Удалённый API может возвращать данные маршрутизации, но не URL произвольного модуля или код.

Ключевая формулировка §3.2: «Дополнительные плагины или иные подключения в виджет не должны грузиться с внешних ресурсов».

[Структура виджета](https://www.amocrm.ru/developers/content/integrations/structure) описывает manifest, script, изображения, локализации и init_once. [Настройки Web SDK](https://www.amocrm.ru/developers/content/web_sdk/settings) требуют onSave с результатом true либо Promise. Это не разрешает менять синхронные результаты остальных callback на Promise.

```sh
python3 scripts/prepare-pv02-legacy.py --source /path/to/rakurs-widgets-dev
```

Результат — игнорируемые Git каталоги pilots/<product>/dist-package/widget. Скрипт проверяет каждый хэш до записи, не обращается в сеть и отказывается перезаписывать существующий dist-package. Для отдельной копии используется --output-root /path/to/empty-output. Новый bootstrap может быть добавлен поверх staging-каталога отдельным шагом сборки. Скрипт не добавляет отсутствующий шаблон и не объявляет snapshot пригодным для активации. Минифицированные библиотеки и неиспользуемые файлы требуют отдельной подготовки перед модерацией.

Версия CopyLead в SSD/public/widgets отличается от widgets-dev: другой script, manifest, библиотеки и шаблоны. Их смешивание создаст непроверенный третий вариант. Снимок widgets-dev выбран для воспроизводимого локального кандидата, а не объявлен опубликованной production-версией. ColorLeads в SSD/public/widgets не найден.

## Контракт совместимости legacy

Оба entrypoint — AMD define, возвращающий конструктор; его нужно вызвать с amoCRM widget в this, сохраняя callbacks и методы render/get_settings/list_selected. Оригинальный params.path должен указывать на корень пакета с lib/, templates/ и images/. Изменять его глобально в ходе асинхронной загрузки нельзя.

| Сценарий | Особенность |
| --- | --- |
| ColorLeads | init возвращает Promise; manifest init_once=false. card_sdk: loadElements, linkCard, searchDataInCard также асинхронные. |
| CopyLead | render/init/bind_actions/onSave/dpSettings синхронные; manifest init_once=true. |
| CopyLead Salesbot | onSalesbotDesignerSave синхронно возвращает JSON-строку. Оборачивать этот результат в Promise нельзя. |
| CopyLead список | callbacks.leads.selected — вложенный callback; копирование только верхнего уровня недостаточно. |
| Общие legacy helpers | lib/tools.js и lib/app/account.js — глобальные scripts без AMD exports; используют глобальные $/AMOCRM/rkrsTools/rkrsAccount. Их загрузка должна происходить после jQuery. |

Одинаковый URL пакета нельзя одновременно переопределять новым содержимым: это смешает requirejs-кэш и версии относительных зависимостей. При смене owner требуются завершение старого экземпляра и новая загрузка в контролируемом lifecycle; простого вызова конструктора другого frontend недостаточно.

Сохранённые legacy endpoints намеренно не переписаны: ColorLeads читает SSD `/api/v1/rkrs_color_leads/getSettings`, CopyLead использует `/widget/settings/get`, `/widget/rkrs_copylead/setCopyLead`, DP/Salesbot webhook на SSD. Helpers обновляют `/api/widget/account/update`; ActivationRakurs выполняет старый процесс установки. Это legacy-ветка. Она не подходит для новой Core-установки с техническим SSD-зеркалом без коммерческих побочных эффектов. Переносить её установку под новую вывеску нельзя.

## Найденные препятствия для переключения

1. ColorLeads `settings` запрашивает отсутствующий `templates/amo-widget-card-base.twig`. Snapshot сохранён без выдуманного шаблона. Требуется сравнение с опубликованным архивом и отдельное исправление с проверкой страницы настроек.
2. В обоих legacy entrypoint нет destroy. В ColorLeads два MutationObserver живут в замыканиях init; отключаются только на beforeunload. Debounce хранит timeoutId в своём замыкании. SPA-переход и смена владельца их не останавливают.
3. Общий ActivationRakurs регистрирует анонимный document.click и обработчики полей, создаёт IMask и таймеры, запускает fetch без cancellation. Экземпляр и callback также записываются в общие window/static поля.
4. CopyLead содержит неназванные jQuery handlers, модальные окна и AJAX callbacks, способные завершиться после ухода со страницы. Его render запускает сетевые чтения. Vue UMD render-функции скрывают mount instances.
5. Browser CRM-запросы и SSD endpoints в старых библиотеках обходят будущий общий SDK. Обёртка не меняет их авторизацию, лимитирование или право исполнения. Это отдельная причина не разрешать business cutover из ПВ-02.

Внешний адаптер не может надёжно получить closure-local ресурсы. Глобальная подмена MutationObserver/setTimeout/jQuery для их перехвата затронет другие виджеты и amoCRM. Без изменений legacy lifecycle безопасное destroy обещать нельзя. В provenance legacy_cleanup_supported=false и runtime_activation_allowed=false; сборка кандидата не должна снимать этот запрет.

Минимальное исправление после сверки production baseline: внутри legacy хранить registry observers/timers/listeners/requests; namespaces для jQuery; dispose для ActivationRakurs, IMask и Vue mounts; отмена чтений и generation guard на поздние callbacks; сохранение operation identity для уже отправленных записей. destroy должен завершаться только после остановки исполнения. Если операция уже отправлена, отмена HTTP не является доказательством отмены внешнего эффекта. Для неизвестного результата нужен отдельный протокол из ПВ-01.06.

## Приёмка перед живым пилотом

- Зафиксировать действующие integration ID/client_id, widget_code, опубликованные версии и ZIP-хэши; сверить с локальными snapshot. Отдельно подтвердить account ID demorkrs.
- Подключить реализованный route endpoint и его авторизацию. Локальная заглушка в тестах не является серверным routing-контрактом. Проверить недоступность сервера, устаревшие поколения, некорректные ответы и отсутствие двойного владельца.
- Устранить перечисленные lifecycle blockers, отсутствующий шаблон и подтвердить загрузку всех зависимостей в реальном RequireJS amoCRM; проверить список, карточку, настройки, DP и Salesbot.
- Установить кандидаты в demorkrs; зафиксировать архивы, время, аккаунт, тестовые данные, результаты и скриншоты. Сравнить бизнес-поведение с baseline, включая повторную установку, быстрые SPA-переходы, destroy во время AJAX и повторное открытие настроек.
- Для CopyLead проверить однократность создания сделки через кнопку, DP и Salesbot; не считать лишь отсутствие JS-ошибок успехом. Для ColorLeads проверить правила, канбан/список и отсутствие оставшихся observers после отключения.
- Подготовить читаемые исходники необходимых библиотек и очистить пакет по правилам модерации. Получить отдельное подтверждение политики remote-code, если этот режим нужен; пройти модерацию ZIP. Это внешние результаты, они не заменяются unit-тестами.

До этих проверок ПВ-02.04/.05 — кандидаты и evidence для дальнейшей приёмки, а не завершённый публичный выпуск.
