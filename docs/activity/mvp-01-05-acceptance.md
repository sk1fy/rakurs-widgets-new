# Матрица проверки MVP-01.05

Состояние доказательств на 2 ноября 2026 года. Это запись проверок и открытых
вопросов, а не утверждённая приёмка или подтверждение нового rollout.
Изменение затрагивает live-контроллер панели сотрудников. Backend, CAS,
формат команд, выдача токенов и хранение неопределённых команд не меняются.

## Уровни доказательств

Автоматические проверки используют настоящий контроллер и ответы SDK в памяти.
`live-runtime.test.js` собирает настоящий UMD через Vite с origins `.invalid`,
монтирует runtime и Vue на поддерживаемом маршруте `/leads/detail/12`.
`live-reliability.test.js` использует настоящий DOM-селектор native-кнопки
и удержанные ответы. Эти проверки не подтверждают живую авторизацию amoCRM.

[Браузерный fixture](../../rkrs_activity_panel/widget-app/fixtures/README.md)
использует те же контроллер, runtime и Vue с SDK в памяти. Обычный симулятор
использует отдельную локальную модель. Его поведение не является доказательством
работы live-транспорта.

Независимый проход в браузере на новом локальном fixture подтвердил ошибку
и Refresh, принятый disabled, отсутствие hidden-чтений, одно удержанное чтение
между tick, возврат после скрытия во время owned-state и единственную stop-команду.
После подтверждённого completion очередь пуста, кнопка старта недоступна.
Destroy и повторный render сохраняют одну панель без повторного stop.

Наблюдения установленного MVP-01.04 сделаны агентом через браузер в аккаунте
`amotehrkrs`, на тестовой сделке `39246629`. Новый артефакт в CRM не установлен.
Результаты одного аккаунта не распространяются на все роли, DOM-экраны и вкладки.

## Поведение видимых элементов

Селектор сценария меняет представление без автоматического переключения
интервала. При активном live Imbox другие сценарии заблокированы до Stop.
Заголовок задачи и стрелка раскрывают очередь. Вкладки очереди меняют фильтр.
Очередь показывает до пяти строк, ссылка оставшихся открывает `/todo/list`
в новой вкладке. Подписи типа, сделки, даты и времени поступают из Gateway.
«Связанные» группирует серверные related-строки, пустой список сообщает об отсутствии.

Правая кнопка задачи открывает активную карточку либо явно запускает следующую
задачу и открывает её карточку. Injected card action запускает, переключает или
останавливает соответствующую задачу. Во время Imbox новый card start заблокирован.
Меню «Ещё» содержит completion, pause, history и settings. Крестик, Escape
и внешний pointer закрывают popover. Глобальных hotkeys старта и остановки нет.

Список Imbox выбирает наблюдаемый DOM-диалог. При смене выбранного работающего
диалога сначала подтверждается Stop. Start запускает выбранную активность,
Stop останавливает подтверждённый интервал. Таймер вычисляется по server timestamp.
Кнопки ошибок и «Обновить / повторить запрос» вызывают существующее refresh/recovery.
Флажок компактности меняет личный вид. «Общие настройки аккаунта» открывает
выданную сервером ссылку, требует разрешённых popup и административного доступа.

## Открытые решения о паритете

Старый виджет определял Imbox по выбранному DOM-ряду или недавнему кэшу при
неполном маршруте. Текущий требует `/imbox/<id>` и соответствующий DOM-диалог.
Старый автоматически прерывал task/other при входе в Imbox. Текущий начинает
автоматически только из idle или собственного Imbox-интервала. Изменение этих
правил и добавление hotkeys требуют продуктового решения. Эта работа их сохраняет.

Подтверждение native completion хранится отдельно от видимых строк в приватном
Set контроллера по ID задачи. Пропуск строки, неполная или stale очередь и фильтр
будущих задач сохраняют подтверждение. Видимая строка полной non-stale очереди
только предлагает кандидата на повторное открытие. Контроллер читает live detail
и принимает только тот же ID и владельца с явным `is_completed === false`.
`fetched_at` обозначает время записи кэша, а не порядок завершения задачи.
Даже более новый кэш не доказывает, что задача снова открыта.

Ошибка, некорректный detail и скрытая вкладка сохраняют подтверждение.
Следующий подходящий refresh повторяет проверку. Прочитанные повторные открытия
ждут финальной проверки queue ticket и revision перед изменением Set и проекции.
Команды пользователя не ждут этих чтений и делают их поздние ответы неактуальными.
Новое native подтверждение также отменяет старое чтение очереди.
Контроллер хранит подтверждение до доказанного повторного открытия или dispose.
Set может расти с числом подтверждённых задач за время жизни контроллера.
Browser storage и новый контроллер эти данные не восстанавливают.

Это проверяют cached timestamp, live reopening, omission, future filtering,
absent confirmation, detail errors, hidden, held reopening, invalid detail
и disposal тесты в `live-reliability.test.js`.

## Воспроизводимые команды

Из `rkrs_activity_panel/widget-app` выполняются следующие команды.

```sh
node --test tests/live-reliability.test.js tests/live-runtime.test.js
npm test
npm run build:preview
```

На переданном дереве воспроизводитель показал ложный старт после native completion.
Полная non-stale очередь с `fetched_at=1800000010` пришла после завершения
в `1800000020`. Detail по-прежнему показывал completed, но очередь выбрала задачу
и добавила «Взять в работу». Проверка с `fetched_at=1800000030` также воспроизвела
ошибку. До изменения Set и live detail targeted suite дал 24 успешных проверки
и 9 ожидаемых падений. Проверки охватывали ложное открытие, зависимость от времени,
ошибку detail, hidden и invalidation команды. После исправления проходят
39 targeted проверок и все 143 проверки `npm test`. Полный набор включает сборку
релиза и существующие проверки CAS, fresh-token и recovery.
Локальные сборки не являются установленным выпуском.
