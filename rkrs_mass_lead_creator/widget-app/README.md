# Прототип «Массовое создание сделок»

Локальная демонстрация пути «фильтр контактов → выбор → настройка → план → создание сделок и задач → результат». Запись в amoCRM не выполняется.

## Запуск

Node.js 22.12+ и npm:

```sh
cd /Users/nikpeskov/Projects/rakurs/rakurs-widgets-new/rkrs_mass_lead_creator/widget-app
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5176/`. Команда сначала собирает удалённый модуль, затем стенд. Стенд грузит виджет через RequireJS: `release.json` → UMD с хешем → список контактов.

После изменения виджета (`WidgetApp.vue`, компоненты, `model.js`, `schedule.js`, `runtime.js`, `widget.css`, `../widget/script.js`) выполните `npm run release` и обновите страницу.

## Экраны

1. **Список контактов.** Поиск, фильтры по тегу, источнику и открытой сделке, страницы по 20. Отдельно «выбрать страницу» и «выбрать все N по фильтру». Если выбрано больше видимых строк, это написано прямо. Панель массовых действий показывает точное число.
2. **Настройка.** Воронка, порядок менеджеров, длительность, дневной лимит, тег, текст задачи. График кабинета на этом шаге только показывается.
3. **План.** Сводка, распределение по менеджерам и дням, таблица «контакт → сделка → ответственный → задача → время». Кнопка запуска подписана количеством и молчит, пока план нельзя выполнить.
4. **Создание и результат.** Прогресс, затем статус каждой строки. Можно открыть локальную карточку сделки. «Вернуться к контактам» и «Показать партию». Своей отмены нет.

Панель **Демо** готовит девять сценариев, квоту «Безлимитный», пустой список, ошибку загрузки, замороженное «сейчас» и график кабинета. Сброс всего набора — только там.

## Допущения демо

- **Расписание.** Шаг = доступные минуты окна / число задач в окне. Длительность — другое число: срок задачи = начало + длительность. Если срок не входит в окно, в этот день ставится только помещающийся префикс, остаток пересчитывается на следующем рабочем дне. Длительность больше шага даёт предупреждение о пересечениях. Длительность больше всего окна запрещает запуск. Старт внутри смены начинается с текущего момента, не в прошлом. После конца дня, в выходной или праздник план начинается со следующего рабочего окна. Один календарь кабинета, Europe/Moscow, UTC+3. По умолчанию пн–пт, 09:00–18:00. «Сейчас» заморожено на `2026-10-06T09:00:00+03:00`.
- **Лимит менеджера** считается только по новым задачам этой партии. Уже существующую загрузку прототип не знает.
- **Квота 250** — отдельно: сколько контактов можно обработать за локальный день кабинета. Списание идёт по успешно созданным сделкам этого дня. Если выбор больше остатка, запуск закрыт и часть партии молча не создаётся. «Безлимитный» только выключает предел, оплаты нет.
- **Дедупликации нет.** Колонка «Открытая сделка» — предупреждение. Повторный отдельный запуск по тому же контакту может создать ещё одну сделку. Повтор одного и того же id внутри одной партии игнорируется.
- **Телефон.** Без номера контакт нужно явно исключить: номер не выдумывается. Из нескольких номеров по умолчанию берётся первый, его можно сменить. Пустой текст задачи оставляет в задаче телефон. Пустой тег не блокирует запуск, но предупреждает, что партию будет трудно найти.
- **Этап** не выбирается: берётся первый рабочий этап воронки.
- **Отпуск** менеджера — только подсказка, задачи из-за него не переезжают.
- **Отмены нет.** Удалить результат прототипа целиком можно только сбросом демоданных.
- **Ошибки.** Демосценарий может создать сделку без задачи или не создать сделку. Повтор делает только отсутствующий шаг и не копирует успешную сделку.

Контакты, менеджеры, воронки и телефоны вымышлены. Телефоны вида `+7 900 000-xx-xx`, звонки по ним не выполняются. Список из 130 контактов собран из фиксированных имён, без `Math.random` при отрисовке.

## Архитектура

| Файл | Назначение |
| --- | --- |
| `../widget/script.js` | AMD-загрузчик, callbacks amoCRM, `release.json` и UMD |
| `src/runtime.js` | Shadow DOM, монтирование, ключ localStorage |
| `src/schedule.js` | Round-robin и укладка задач в календарь |
| `src/model.js`, `src/demo-data.js` | Выбор, квота, партии и фикстуры |
| `src/WidgetApp.vue`, `src/components/` | Список, мастер, демопанель, карточка |
| `src/Preview.vue` | Оболочка демонстрационной CRM |

Публичный контракт модуля: `registerWidgetInstance`, `mountPanel`, `openSettings`, `unmountAll`. Повторный `mountPanel` не дублирует панель. `destroy` снимает только свой экземпляр. Если бандл придёт после `destroy`, загрузчик его не монтирует.

Сохранение: `rkrs_mass_leads_prototype_v1:<accountId>:<userId>`. В стенде это аккаунт `999201`, пользователь `999202`, поддомен `demo`, область `clist`.


`npm test` собирает релиз и прогоняет `node:test` для чистого планировщика. Предпросмотр собранного стенда: `http://127.0.0.1:4176/`.

## ZIP

В `../widget/script.js` стоит плейсхолдер `__RKRS_MASS_LEADS_ASSETS_URL__`. После размещения `dist-remote/` на HTTPS:

```sh
npm run package:widget -- --assets-url https://YOUR-HOST/widget-assets
```

Архив: `dist-package/rkrs-mass-leads-prototype.zip`. Внутри загрузчик, manifest, локализация и картинка, без UMD. Это по-прежнему прототип без записи в живую CRM.
